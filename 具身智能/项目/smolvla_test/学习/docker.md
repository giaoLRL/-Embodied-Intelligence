# 什么是docker？
Docker 本质是 "应用打包 + 隔离运行"的工具，解决" 在我电脑上能跑，在你电脑上跑不了 " 的环境一致性问题。

## 一、镜像
把应用 + 依赖 + 配置 + 运行环境完整打包成一个只读文件，在任何支持 Docker 的机器上运行结果完全一致

镜像不是一个大文件，而是分层叠加的结构（这是 Docker 高效的核心）



### 1.分层复用
- 所有镜像都基于一个基础镜像（如 ubuntu:22.04、alpine:3.19）构建
- 相同层只会在本地存储一份，不同镜像可以共享

### 2.不可变性
- 镜像一旦构建完成就不能修改
- 你对运行中容器的修改不会影响镜像
- 要修改应用只能重新构建镜像（这保证了环境一致性）

### 3.镜像仓库
- 镜像可以推送到远程仓库（如 Docker Hub）共享
- 你用 docker pull 就是从仓库拉取镜像
- 标签（Tag）是镜像的版本号（如 nginx:1.25.3，不写默认是 latest）


## 二、容器：镜像的 "运行实例"
- 容器是基于镜像创建的可读写层 + 隔离的运行环境
- 一个镜像可以创建无数个完全相同的容器
- 容器本质是宿主机上的一个特殊进程（不是虚拟机）

### 1.写时复制（Copy-on-Write）
- 容器启动时，在镜像的只读层上添加一个可读写层
- 所有对容器的修改（如写文件、改配置）都只发生在这个可读写层
- 容器删除时，这个可读写层也会被删除（这就是为什么容器默认不持久化数据）

### 2.生命周期管理
- 容器有明确的生命周期：创建 → 启动 → 运行 → 停止 → 删除
- 停止的容器不会自动删除，它的可读写层还在
- 容器重启后，可读写层的内容会保留（但不建议依赖这个）
### 3.前台 / 后台运行
- 容器默认在前台运行，会占用终端
- 加 -d 参数让容器在后台运行（守护进程模式）
- 容器的生命周期与它的主进程绑定：主进程退出，容器就停止
