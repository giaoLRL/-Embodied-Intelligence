# 什么是docker？
Docker 本质是 "应用打包 + 隔离运行"的工具，解决" 在我电脑上能跑，在你电脑上跑不了 " 的环境一致性问题。

docker容器能跨系统运行的核心原因是因为容器里面同时打包了**系统依赖文件**。不同的系统之间无法运行，不是因为内核，内核都是共用的，最大的区别是系统依赖和基础依赖的不兼容。

## 一、镜像
把应用 + 依赖 + 配置 + 运行环境完整打包成一个只读文件，在任何支持 Docker 的机器上运行结果完全一致

镜像不是一个大文件，而是分层叠加的结构（这是 Docker 高效的核心）



### 1.分层复用
- 所有镜像都基于一个基础镜像（如 ubuntu:22.04、alpine:3.19）构建
- 相同层只会在本地存储一份，不同镜像可以共享

### 2.不可变性
- 镜像一旦构建完成就不能修改
- 你对运行中容器的修改不会影响镜像
- 要修改应用只能重新构建镜像（这保证了环境一致性）

### 3.镜像仓库
- 镜像可以推送到远程仓库（如 Docker Hub）共享
- 你用 docker pull 就是从仓库拉取镜像
- 标签（Tag）是镜像的版本号（如 nginx:1.25.3，不写默认是 latest）


## 二、容器：镜像的 "运行实例"
- 容器是基于镜像创建的可读写层 + 隔离的运行环境
- 一个镜像可以创建无数个完全相同的容器
- 容器本质是宿主机上的一个特殊进程（不是虚拟机）

### 1.写时复制（Copy-on-Write）
- 容器启动时，在镜像的只读层上添加一个可读写层
- 所有对容器的修改（如写文件、改配置）都只发生在这个可读写层
- 容器删除时，这个可读写层也会被删除（这就是为什么容器默认不持久化数据）

### 2.生命周期管理
- 容器有明确的生命周期：创建 → 启动 → 运行 → 停止 → 删除
- 停止的容器不会自动删除，它的可读写层还在
- 容器重启后，可读写层的内容会保留（但不建议依赖这个）
### 3.前台 / 后台运行
- 容器默认在前台运行，会占用终端
- 加 -d 参数让容器在后台运行（守护进程模式）
- 容器的生命周期与它的主进程绑定：主进程退出，容器就停止

## 五、Dockerfile：镜像的 "构建说明书"
### 为什么发明dockerfile？
早期的docker是没有dockerflie的，会出现一个问题：所有的依赖都需要手动安装，缺点就是效率低，且有很多中间层文件，还是会存在不兼容的情况。此外还会有不可追溯，不可维护，体积臃肿的问题。

将基础设施即代码的容器化落地，用纯文本规范配置，可以纳入git等版本控制系统，实现团队协作，每个人只要文本一致都能构建出完全一样的镜像。

### 语法
#### 1.基础核心指令
FROM：指定基础镜像,例如
```
FROM ubuntu：22.04
```
ARG：定义构建时参数（仅在构建中有效）：
```
ARG
NODE_VERSION=18
```
LABEL：为镜像添加元数据（作者、版本、描述）：

#### 2.文件与目录操作指令
copy：从宿主机复制文件/目录到镜像中：
```
COPY ./SRC
/app/src
```
ADD:增强版复制指令：
```
ADD
https://example.com/file.tar.gz
/app/
```
WORKDIR:设置工作目录（后续指令的默认路径）
```
WORKDIR /app
```
#### 构建执行指令
```dockerfile
# RUN：在构建阶段执行命令（创建镜像层）
# 推荐将多个命令合并为一条，减少镜像层数
RUN apt-get update && \
    apt-get install -y nginx && \
    apt-get clean && \
    rm -rf /var/lib/apt/lists/*
```
- **重要原则**：每一条RUN指令都会构建一个新的镜像层，因此应尽量去合并相关命令
- 上述示例通过&&连接命令，并在最后清理缓存，大幅减小镜像体积

#### 4.运行时配置指令
ENV：设置环境变量（构建和运行时都有效）
```
ENV
NODE_ENV=production
```
EXPOSE:声明容器运行时监听的端口
```
EXPOSE 80 443
```
USER：指定运行容器的用户：
```
	USER appuser
```
VOLUME:	创建匿名挂载点:
```
VOLUME ["/data"]
```

# 构建完镜像后的操作
构建镜像就相当于构建了一个**小电脑**，挂载本地文件就是**共享本机文件夹**，运行命令就是**开机+开显卡+运行程序**。

基于镜像启动容器
```
docker run [可选参数] 镜像名称/镜像ID [容器启动后执行的命令]
```
参数必须写在镜像前：

| 参数 | 全称 | 作用 | 示例 |
| ---- | ---- | ---- | ---- |
| -d | --detach | 后台运行容器（退出终端不关闭） | -d |
| -p | --publish | 端口映射（宿主机端口：容器端口） | -p 8080:80 |
| --name | - | 给容器起自定义名称（方便管理） | --name my-nginx |
| -v | --volume | 目录挂载（本地文件 ↔ 容器文件同步） | -v /本地目录:/容器目录 |
| -e | --env | 设置环境变量（数据库密码等） | -e MYSQL_ROOT_PASSWORD=123456 |
| --rm | - | 容器停止后自动删除（测试用） | --rm |


带端口映射：
```
docker run -d --name my-nginx -p 8080:80 nginx
```
> 端口映射使用来连接容器内部和电脑的，不然两个环境完全隔离。

查看启动中的容器
```
docker ps
```

CONTAINER ID：	容器的唯一短 ID（完整 ID 可通过docker inspect查看）  
IMAGE：	容器基于的镜像名称（容器是镜像的运行实例）  
COMMAND	：容器启动时执行的命令  
CREATED：	容器的创建时间  
STATUS	：容器状态：✅ Up xx = 运行中🛑 Exited(xx) = 已停止 / 退出  
PORTS：	端口映射（宿主机端口：容器内部端口）  
NAMES：	容器名称（Docker 自动生成，也可手动指定）  

### 文件挂载
命令：
```
# 端口映射（网络）
-p  本地端口:容器端口

# 挂载（文件）
-v  本地路径:容器内路径
```
挂载无非就是将容器路径和本机电脑的路径进行映射。

### 镜像和容器的关系是什么？
镜像 = 静态模板 / 安装包

容器 = 模板跑起来的动态实例 / 正在运行的程序

核心关系：一个镜像，可以同时启动无数个独立容器；删掉容器，镜像不会消失
