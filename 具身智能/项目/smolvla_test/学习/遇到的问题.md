# SmolVLA 微调全流程问题总结

## 一、遇到过的所有问题及原因

### 1. 环境与基础设施
- **天翼云开发机找不到公网IP、端口不是22、用户名是batchcom**  
  科研助手平台和普通ECS不同，它有自己的规则。AI们费了些时间才在实例详情里找到正确的连接方式。
- **SSH连接超时、VSCode连不上**  
  安全组IP白名单没配置对、本地网络封了非标准端口（30119）。最后靠浏览器自带的终端解决了。
- **JupyterLab终端能用，但下载数据集非常慢**  
  开发机外网受限，无法直接访问HuggingFace。通过设置 `HF_ENDPOINT=https://hf-mirror.com` 镜像源解决，中途也遇到过超时，多次重试后成功。
- **挂载科研文件，容器路径选 `/data`**  
  一开始对天翼云存储不熟，后来明确用“科研文件”做持久化，路径填 `/data`，保证关机不丢数据。

### 2. 依赖与代码兼容性
- **LeRobot版本混乱（0.4.4 vs 0.5.1），Python版本冲突**  
  官方文档要求 `lerobot>=0.5.0` 且 Python 3.12，但AI们的镜像自带了 Python 3.10。来回创建了多个conda环境，最后在云上用 `smolvla`（Python 3.10 + LeRobot 0.4.4），本地用 `.venv`（Python 3.12 + LeRobot 0.5.1）分别成功。
- **`lerobot_train.py` 命令行参数格式变更**  
  0.4.4 用 `--policy=smolvla`，0.5.1 用 `--policy.type=smolvla`。直接复制模板命令导致报错多次。
- **Groot策略的dataclass错误**  
  LeRobot库自带的一个bug（`backbone_cfg` 默认参数问题），AI们不得不反复注释掉相关导入甚至重命名文件夹来绕过。
- **本地PyTorch版本冲突与CPU版本反复安装**  
  镜像源无法提供合适版本（`2.10.0+cu121` 不存在，`2.6.0+cu124` 也找不到），最后用 `2.5.1+cu121` 才成功。中间多次装上CPU版，其实是因为没有严格指定版本号并带上 `+cu121` 后缀。

### 3. 数据与训练配置
- **数据集下载中断、镜像超时**  
  使用 `hf download` 断点续传，加上镜像源多次重试才完成。
- **配置参数命名坑**  
  `batch_size`、`optimizer.lr` 等在不同版本写法不同（有些需 `--policy.optimizer_lr`），导致训练启动报错。
- **训练保存的检查点只有 `training_state` 和 `pretrained_model` 文件夹**  
  一度以为模型没保存，最后发现完整权重（`model.safetensors`）就在 `pretrained_model` 里。

### 4. 本地部署与推理
- **模型加载方式不断调整**  
  一开始用相对路径 `"./smolvla_model"` 被 HuggingFace 验证拦截，后来改成绝对路径、加 `local_files_only=True` 还是失败，最后用手动读取 `config.json` 和 `model.safetensors` 再实例化策略的方式才成功。
- **进程崩溃（退出代码 0xC0000005）**  
  PyTorch 版本不匹配导致，彻底删除虚拟环境并重建后解决。

## 二、哪些问题卡了很久，下次要注意

1. **平台特定规则提前查**  
  天翼云科研助手的端口、用户名、白名单、镜像选择，应当在创建之前就找官方文档或客服问清楚，不要用默认ECS经验去套。
2. **先确定软件版本矩阵再动手**  
  LeRobot 和 PyTorch、Python 的版本对应关系，不要凭感觉装。应该先查阅官方文档或 GitHub 的 setup 说明，明确支持的组合。
3. **网络问题永远要准备国内镜像**  
  pip、HuggingFace、GitHub 全部要准备镜像源，并且随时准备断点续传（hf download、tmux 会话保护）。
4. **代码库自身的bug要敢于修改源码**  
  Groot 的 dataclass 错误是库代码问题，如果早点定位并注释掉相关行，能节省大量时间。未来可以优先搜索报错信息，看是否是已知 issue。
5. **命令行参数务必用 `--help` 确认**  
  每个工具的参数名在不同版本可能微调，启动前先 `python -m lerobot.scripts.train --help` 或 `lerobot-train --help` 看一眼支持的写法，避免盲写。

## 三、哪些点需要自己自己学习，不能全依赖 AI

1. **Linux基础操作**  
  文件目录跳转、权限、环境变量（`export`）、tmux 会话管理（`tmux new -s`, `tmux attach -t`, `Ctrl+B D`）这些必须亲手操作过才能形成肌肉记忆。
2. **Python虚拟环境管理**  
  理解 conda 和 venv 的差异，知道如何创建、激活、退出，以及为什么 PyCharm 的解释器要和终端一致。这是保证环境不混乱的核心技能。
3. **读懂报错信息**  
  不要一看到错误就复制给AI。先看最后一行：`ModuleNotFoundError` 说明包没装；`HashError` 说明下载损坏；`TypeError: non-default argument follows default argument` 一般是 dataclass 定义问题，可以尝试注释掉。这种“日志阅读能力”必须自己磨练。
4. **pip和包管理**  
  知道 `--index-url` 指定下载源，`-i` 镜像源怎么用，`--no-cache-dir` 清缓存。明白 `+cpu` 和 `+cu121` 的区别，学会用 `pip list | grep torch` 快速查看当前版本。
5. **模型文件结构认知**  
  一个微调好的模型文件夹里需要 `config.json`、`model.safetensors`、`preprocessor_config.json` 等，知道它们的用途，以及加载时路径到底指向文件夹而非文件本身（除非手动构建策略对象）。
6. **训练流程与调参基本概念**  
  虽然这次超参是AI给的，但自己应该能解释 `batch size`、`learning rate`、`steps`、`chunk size`、`freeze_vlm` 的含义，以及 loss 下降曲线怎么看。这才是自己真正学会微调的标志。
