# HAlO

## 需要理解的命题
### 1.推理是实现机器人智能的核心环节
#### （1）推理是区分自动化与智能的本质边界

传统工业机器人的核心逻辑是示教再现 / 预编程执行：只能在高度结构化的工厂环境中，重复预设的固定轨迹，一旦环境出现任何超出预设的变化（比如物体位姿偏移、光照变化、出现障碍物），就会直接失效。

而机器人智能的核心定义，是在非结构化、动态、未见过的真实世界中，自主完成复杂任务。推理能力，就是让机器人从「只会按预设指令干活」，变成「能自己想明白 “要做什么、该怎么做、出了问题怎么修正”」的核心。

#### （2）推理是打通「感知 - 决策 - 执行」机器人闭环的核心枢纽
机器人完成任务的完整链路是：环境感知 → 场景理解 → 任务决策 → 动作执行。

当前机器人技术的瓶颈早已不是「感知」（计算机视觉已经能精准识别物体、位姿、场景），也不是「执行」（机械臂、电机的控制精度已经满足绝大多数场景需求），而是中间的 “决策环节”—— 如何把感知到的海量视觉 / 力觉信息，转化为符合任务目标的、可落地的动作序列。

推理正是这个环节的核心：
- 它能把高层语言指令（比如 “把瓶子扔进垃圾桶”），拆解为「定位瓶子→调整抓手姿态→稳定抓取→定位垃圾桶→移动避障→松开投放」的可执行子目标；
- 它能实时校验执行效果（比如瓶子滑了、没抓稳），并自主修正动作，而不是执行完预设步骤就停止；
- 对应论文中的 EM-CoT 设计，正是通过「文本推理轨迹 + 视觉子目标」的多模态推理，完美衔接了高层语义意图和底层动作控制，这也是无推理的端到端策略永远无法实现的。

#### （3）推理是解决长时序复杂任务的唯一可行方案
真实世界的绝大多数任务，都是长周期、多步骤、有强依赖关系的长 horizon 任务（比如泡一杯咖啡、整理桌面、组装零件），而非一步就能完成的简单动作。

传统端到端的机器人策略，是直接把视觉输入映射为动作输出，没有中间的推理过程，会出现两个致命问题：
- 长任务中误差持续累积，执行到一半就彻底偏离目标；
- 无法处理任务中的分支情况（比如咖啡机没开、没有牛奶了），只能卡死在预设流程里。
而推理能力（尤其是论文中用到的思维链 CoT 推理），能把长任务拆解为多个独立、可校验的短子目标，每一步都有明确的逻辑闭环：
- 先通过推理明确「当前步骤有没有完成」，再决定「下一步要做什么」；
- 遇到意外情况，能通过推理重新规划路径，而非直接失败；
- 这也是为什么论文中，加入 EM-CoT 推理后，HALO 在长时序、高难度任务上的成功率，比无推理的版本实现了跨越式提升。

#### （4） 推理是机器人实现泛化能力（OOD）的核心支撑
机器人智能的终极考验，从来不是「在训练过的环境里做到 100% 成功」，而是在从未见过的新环境、新物体、新任务中，依然能完成目标—— 也就是行业常说的分布外（OOD）泛化能力。

而泛化能力的核心，就是抽象推理能力：
- 没有推理的模型，只是在拟合训练数据的分布，只会 “识别训练过的杯子、执行训练过的抓取动作”，一旦换成没见过的碗、瓶子，就完全无法完成 “倒水” 任务；
- 有推理能力的机器人，能通过推理抽象出任务的本质（“倒水” 的核心是「找到可装水的容器、抓稳、倾斜到目标容器上方、控制流速」），而非记住训练中的物体特征、动作细节，因此能适配无限多的新场景。

#### 5. 推理是实现自然人机交互的核心前提
真实场景中，人类给机器人的指令，从来都不是精确到每一步的动作指令，而是模糊的、高层级的、带常识属性的意图：
- 人类说 “收拾一下桌子”，不是让机器人把所有东西都扔进垃圾桶，而是要把杂物归位、垃圾扔掉、餐具放到水槽；
- 人类说 “帮我倒一杯温水”，不是让机器人随便倒水，而是要先接冷水、再加热水，控制温度不烫嘴。
这些意图的理解、常识的调用、任务的拆解，全部依赖推理能力。没有推理，机器人只能执行 “移动到 X 坐标、抓手闭合 Y 毫米” 这类精确的底层指令，永远无法实现和人类的自然交互，也就无法走进家庭、办公等真实通用场景。


| 类型 | 核心逻辑 | 核心局限 | 对应你论文中的案例 |
| :--- | :--- | :--- | :--- |
| 记忆 | 复述训练数据中见过的内容，无新的推导 | 只能处理训练中见过的完全一致的场景，换场景就失效 | 只能在训练过的干净环境中抓取固定的瓶子，换物体、换环境就失败 |

| 推理 | 基于逻辑链路，从已知推导未知，生成新的决策方案 | 无本质局限，可适配未知场景、修正异常、完成长时序复杂任务 | HALO 搭载 EM-CoT 推理后，同困难场景成功率达到 26.4%，实现跨量级提升 |

1.显示推理具有组合泛化能力

2.具备工作记忆，适应动态变化

4.融合常识与因果推断

5.跨模态对齐，提升鲁棒性

## 3.将文本与图像耦合在单一自回归模型会削弱底层视觉模型VLM的推理能力。
### 1.生成目标与推理目标的本质冲突
**文本**的主要任务是**推理、问答和规划**，最适合的建模方式是**自回归**。

而**图像**的主要任务是**生成、预测和想象**，最适合的建模方式是**扩散，流匹配双向注意力**。

> 推理需要从左到右的因果注意力，关注语义一致性和逻辑链条。
>
> 图像生产，尤其是像素级别的建模，更适合双向上下文或者噪声预测范式，自回归逐像素生成效率极低且容易积累误差。

当把图像强行表示为一串离散视觉 token（如 VQ-VAE 编码），并用同一个自回归 Transformer 去预测这些 token 时，模型被迫用适合推理的架构去做不适合的视觉细节建模，导致两方面都受损。

### 2.视觉Token的信息瓶颈

将连续图像压缩为有限码本中的离散 token，会**丢失大量空间结构和细粒度视觉信息**（尤其是接触、形变、微小位移对机器人操作至关重要的细节）。

VLM 原本可以通过连续视觉特征（如 ViT 输出的 embedding）进行细粒度理解；但为了生成图像，模型不得不学习低质量的离散重建，这种“理解”能力的退化会直接削弱 VLM 的视觉推理。

### 3.训练目标冲突与梯度干扰

单一自回归模型需要同时优化：
- 文本 token 的交叉熵损失（推理）
- 视觉 token 的交叉熵损失（生成）
- （有时还有动作 token）

不同目标的梯度方向和尺度差异很大，导致：
- 模型容量被视觉重建任务分流
- 文本推理任务的信号被淹没，VLM 原先丰富的多模态理解能力被“遗忘”或覆盖

尤其在小模型（1.5B~7B）中，能力竞争更明显，无法像 GPT-4V 那样用巨大容量去“硬解”所有任务。

### 4.注意力掩码的不可兼得
自回归模型使用因果掩码（只能看到过去 token）。

视觉理解（如 VQA）常需要双向上下文（同时看左右、上下像素关系）才能做到准确的场景理解。

强制使用因果掩码去处理图像 token 序列，相当于**限制了 VLM 对视觉信息的全向感知能力**，这是推理能力下降的直接原因。

## 4.通过生成图像视觉模型或视频引导下游动作预测能提高效果。
传统 VLA：观测 → 动作（端到端映射，隐式策略）

HALO：观测 → 文本推理 → 视觉子目标图像 → 动作（显式想象，显式规划）

这里的“视觉子目标”是指：在真正执行动作之前，模型先生成一张预期未来某个时刻的场景图像（比如“手爪已抓住杯子”的画面），然后再基于这张想象图去生成具体的关节动作。

### 1. 提供稠密的空间目标表征，降低动作学习的模糊性
语言指令是语义级的（“把红色杯子放到蓝色盘子上”），无法指定手爪与物体的精确相对位姿、抓取角度、接近方向等。

视觉子目标图像比文本更稠密、空间化：它隐式包含了：
- 物体最终的位置、姿态
- 手爪（或末端执行器）与物体的接触关系
- 场景中所有物体的空间布局

动作生成模块有了这张目标图像后，可以将任务简化为：“如何从当前图像（状态）运动到目标图像（状态）”，这是一个**强约束的几何路径规划问题**，学习难度大幅下降。

### 2. 实现“先验证可行性，再执行”——避免盲目试错
模型生成子目标图像的过程，本质是对世界模型的调用：它会根据当前场景和动作意图，预演未来状态。

如果生成的子目标图像不合理（如手爪穿透物体、物体浮空），模型可以在动作执行前就察觉到错误，并调整推理或重新规划。

这相当于代价极低的“心智试错”，避免了真实物理环境中不可逆的失败（如打翻物体）。

### 3. 分解长时序任务，提供中间密集奖励信号
对于长 horizon 任务（如“开抽屉→拿出柠檬→放入→关抽屉”），直接学习端到端的动作序列需要非常稀少的成功奖励。

中间视觉子目标将长任务切分为多个视觉上可验证的阶段：
例如：
- 子目标1：手爪接近抽屉把手（图像A）
- 子目标2：抽屉被拉开一定距离（图像B）
- 子目标3：手爪捏住柠檬（图像C）
- …

动作模块只需学习从一个视觉目标到下一个视觉目标的短程策略，每个阶段都有清晰的视觉成功判据，避免了长期依赖和稀疏奖励问题。

### 4. 隐式地学习了物理与几何约束，提升泛化性
模型通过大量“观测 → 子目标图像 → 动作”数据，被迫学习：什么样的动作会导致什么样的视觉变化（即前向视觉动力学）。

这种学习不是显式的物理方程，而是隐式的视觉直觉：比如“推物体会使物体平移”、“夹爪闭合会改变物体位置”。

当环境出现未见过的物体、背景、光照时，模型可以利用这种泛化的视觉动力学，想象出合理的子目标图像，从而仍然能够规划出有效动作，而非依赖存下的 exact 记忆。

# HALO 模型专业技术总结

## 一、模型架构
混合 Transformer 是 HALO 论文中使用的一种稀疏多专家架构，其核心思想是：
```
将不同能力（如：文本理解、图像生成、动作预测）分配给独立的 Transformer 专家模块，这些专家拥有各自独立的参数，但通过共享的自注意力机制进行协同交互。
```
### 1. 混合 Transformer（Mixture-of-Transformers, MoT）


- 三个专家模块：文本推理、视觉生成、动作预测
- 共享自注意力机制实现跨专家协作
- 保持各专家原生生成范式（文本自回归，视觉/动作扩散/流匹配）

> #### MoT 与 VLA 算法的关系
> VLA（Vision-Language-Action） 是一类模型的总称，其目标是从视觉和语言输入直接输出机器人动作指令。典型的 VLA 模型如 π0、RDT-1B 等。
> 
> 传统 VLA 的问题
> 
> - 大多数 VLA 采用单一、稠密的 Transformer（如 7B 或 13B LLaMA），同时承担多模态理解和动作生成。
> 
> - 这会导致：
>   - 不同模态的优化目标冲突（比如：文本生成需要因果掩码，图像生成需要双向注意力）
>   - 难以注入复杂的多模态思维链（文本推理 + 视觉想象）
>   - 在长任务和分布外场景下表现脆弱
> 
> #### MoT 对 VLA 的改进（即关系本质）
> MoT 是一种专门为 VLA 算法设计的架构实现方案，使得 VLA 模型能够原生支持“具身多模态思维链（EM-CoT）”。
> 
> 具体关系体现在：
> 
> 1.能力解耦 + 对齐
> 
> MoT 将 VLA 的三大能力（理解、预测、控制）拆分为三个专家，各自训练目标清晰，然后通过共享注意力重新对齐，避免传统 VLA 的“能力混杂”。
> 
> 2.支持异构生成
> 
> VLA 通常需要同时输出文本（推理）、图像（子目标）和动作（连续控制）。单一自回归模型很难高质量完成三者；MoT 允许不同专家使用不同生成范式，更好满足 VLA 的多输出需求。
> 
> 3.实现 EM-CoT
> 
> 论文的核心是让 VLA 模型具备“先思考、再想象、后行动”的能力。MoT 的结构自然贴合这三步顺序：文本专家做推理 → 视觉专家生成子目标图像 → 动作专家输出动作，每一步的条件信息通过共享注意力传递。

> 4.保持通用知识
> 
> 传统 VLA 在微调后容易丢失通用 VQA 能力。MoT 在微调阶段可以只更新动作专家或轻量更新，同时通过共享注意力仍能访问其他专家的通用知识，缓解灾难性遗忘。

### 2. 双路径视觉编码器
- **语义路径**：ViT (SigLIP2-so400m/14)，支持 980×980 分辨率，集成 NaViT
- **空间路径**：预训练 VAE (FLUX)，下采样率 8，潜在通道 16
- 通过 MLP 投影层对齐到 LLM 嵌入空间

### 3. 动作编码/解码
- 线性投影层：连续动作 ↔ LLM 隐藏维度

### 4. 基座语言模型
- Qwen2.5-1.5B Instruct (1.5B)，三个专家共享，总参数 ≈4.5B

### 5. 特殊 Token
- 扩展词表，用于区分推理/视觉/动作阶段

## 二、训练策略

### 两阶段训练
- **阶段一：通用预训练**
  - 数据：VQA (LLaVA-NeXT-779k) + 视觉生成 (OXE + SSv2) + 动作预测 (OXE)
  - 损失：`L_pt = 0.25*L_CE + 0.5*L_MSE + L_L1`
- **阶段二：EM-CoT 微调**
  - 数据：合成 EM-CoT 轨迹 + VQA（防遗忘）
  - 损失：`L_ft = L_r + L_o + L_a`

### 流匹配 (Flow Matching)
- 用于视觉生成和动作预测，比传统扩散更高效稳定

### 关键超参数
| 参数 | 预训练 | 微调 |
|------|--------|------|
| 优化器 | AdamW | AdamW |
| 学习率 | 1e-4 | 5e-5 |
| 序列长度 | 40k | 27k |
| 训练步数 | 90k | 110k(仿真)/80k(真实) |
| 动作块长度 | - | 16(仿真)/50(真实) |
| 输入帧数 | - | 3 |

## 三、EM-CoT 数据合成管道

### 1. 动作原语提取
- 基于夹爪状态和末端位姿，通过速度/位移阈值规则匹配，分割为 move/grasp/release

### 2. VLM 三阶段标注
- **阶段1**：生成连贯任务叙述（时序顺序）
- **阶段2**：分解为 2-5 个语义子任务
- **阶段3**：逐帧对齐子任务，生成第一人称推理（<50词）

### 3. 视觉子目标提取
- 每个子任务的终止帧作为目标图像，广播到该子任务所有帧

## 四、注意力机制

- **预训练**：帧内双向注意 + 噪声 token 双向 + 跨模态因果约束
- **微调**：EM-CoT 专用掩码，非噪声 token 对噪声 token 不可见，严格按文本→视觉→动作顺序
- **加速**：Flex Attention

## 五、其他技术

- **域随机化**：评估鲁棒性（改变外观/光照/背景）
- **真实平台**：Cobot Mobile ALOHA（顶视单目相机，双机械臂）
- **基线对比**：π0, RDT-1B, Diffusion Policy
- **评估指标**：任务成功率（Easy 80.46% / Hard 26.44%）
