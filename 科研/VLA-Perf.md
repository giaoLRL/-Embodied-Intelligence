
2：完成 VLA 推理性能的首次系统性研究：全面覆盖模型设计、硬件选型、部署方式、网络环境四大维度，探究各关键因素对 VLA 推理性能的影响。
3：系统对比 VLA 主流部署方案的性能边界：全面评估端侧、边缘服务器、云端、端边协同等部署方式的性能差异，明确10Hz（可接受）和100Hz（高性能）的实时推理目标，给出了不同场景下 VLA 模型的最优部署策略。

### 研究背景
VLA模型展现卓越，但是实际应用上面必须低延迟，但是模型层与执行层之间有很大的组合空间，先前对于推理性能的优化都是单点优化，比如用小模型、量化、跳层、减少扩散去噪步、异步推理、双系统设计等，没有将所有的关联起来给出最佳的方案，目前学界对 VLA 模型的推理性能全貌仍缺乏系统性认知

### VLA
#### 模型框架
自回归行动专家：
用单一的Transformer来整合视觉观察、解释语言指令并生成行动，以迭代方式一次生成一个行动维度（或标记）。此范式的代表性例子包括RT系列、OpenVLA和Octo

基于扩散的行动专家：
VLM骨干接收视觉和语言输入，而基于扩散的行动专家则关注VLM的KV缓存，并通过迭代优化过程生成行动，其中去噪步骤的数量是一个可配置参数。代表性的扩散风格VLA模型包括πo系列、GR00T、SmolVLA和TinyVLA。
#### 行动预测
每个机器人行动通常包含多个维度，例如机械臂的关节位置、速度或扭矩，或人形机器人的全身关节配置。为了实现平滑稳定的执行，许多VLA模型采用行动分块，即模型在单次推理中预测一系列未来行动，该序列长度称为行动块大小。在行动分块下，可以指定一个执行视野，定义为在执行下一次推理之前实际执行的行数量，其不大于块大小。较大的执行视野可以提高行动平滑度并降低推理频率，但也会降低模型对外部环境变化的及时反应能力。
#### 高效VLA推理
- 减少计算量
- 异步推理和双系统VLA
- 更好的推理系统
### VLA-Perf
#### 输入
所有输入都是可自由配置的参数：VLA模型配置参数与推理系统配置参数
VLA模型配置参数：
- 三大核心组件的基础参数：视觉编码器、VLM 主干、动作专家的层数、隐藏层维度、注意力头数、参数量、FFN 中间维度等；
- 输入输出配置：输入的视觉 token 数、语言 token 数、总序列长度、动作维度（比如单机械臂 7 自由度、双臂 14 自由度）；
- 推理超参数：扩散模型的去噪步数、动作分块大小；
- 特殊模式配置：长上下文的历史时间步数、异步推理参数、双系统流水线的频率配置等。
  
推理系统配置参数：
- 加速器硬件配置：推理用的 GPU / 芯片的峰值算力（BF16/FP16 TFLOPS）、显存大小、内存带宽；
- 部署位置配置：推理跑在端侧、边缘服务器还是云端，各个模型组件分别部署在哪；
- 网络环境配置：上下行带宽、基础网络延迟（支持以太网、WiFi6/7、4G/5G、云网络等全场景）。
#### 输出
在输入参数下的，VLA推理的理论最优性能指标，同时附带全链路的拆解数据，包括：
- 核心主指标：端到端推理总延迟（ms）、对应的推理频率 / 吞吐量（Hz，每秒能完成多少次推理）；
- 瓶颈拆解指标：视觉编码器、VLM 主干、动作专家各自的推理延迟、计算量、内存访问量，以及每个模块是算力瓶颈（计算 - bound）还是内存带宽瓶颈（内存 - bound）；
- 辅助指标：长上下文场景的 KV 缓存大小、总显存占用、网络传输延迟占比、异步 / 双系统模式的理论吞吐量上限等；
- 对比能力：支持同时输入多组模型 / 系统配置，直接横向对比不同方案的性能差异，帮用户筛选最优解。
#### 简单概述
vla-perf将机器人和多个模型组件（视觉编码器，视觉令牌等），模型组件抽象为一个算子在单独的GPU上跑
**输入**先对输入进行参数化，来匹配任意模型和系统组合
- 在模型侧，参数包括视觉编码器、VLM骨干和行动专家的选择；每个模型的输入和输出序列长度；基于扩散的行动专家的去噪步骤数量；行动块大小；以及每个行动的维度
- 在推理侧，参数包括推理硬件的算力峰值、显存大小、网络带宽、推理部署位置、推理模式（异步推理、双系统流水线等），支持各种具有可配置峰值FLOP/s和内存带宽的推理加速器，以及以上传/下载带宽和延迟为特征的网络系统。

**计算延迟建模**，对于给定输入，
- VLA系统的端到端推理延迟被建模为所有组件的模型推理延迟和数据移动延迟之和，单个算子对于计算（总操作数/峰值计算吞吐量）和内存访问（内存字节数/内存带宽）延迟取最大值
- 数据移动延迟建模为网络延迟加传输的数据量/带宽。

**Roofline 模型精准判定其性能瓶颈类型**
roofline整体计算算理论性能最优、定位瓶颈、估延迟的核心工具。对于每个算子计算算法强度（AI），算术强度低：受带宽限制，性能上界由带宽决定；算术强度高：受算力限制，性能上界由峰值算力决定。

**建模保真度**：优化后的系统可以达到VLA-Perf报告的理论屋顶线的 73.3∼82.6%，随着工作负载增加（例如，处理三个相机帧时），差距缩小

#### 标准校准件与万能可调测试：π0 架构衍生的模型
π0 及其衍生架构，是 VLA-Perf 的原生适配原型、唯一验证基准、核心研究载体，二者是原型实践 - 理论建模的双向强绑定关系，VLA-Perf 的所有系统性结论，均基于 π0 全系列衍生架构的全维度遍历分析得出，同时 VLA-Perf 也反向为 π0 未来的衍生架构迭代，提供了可落地的设计准则。
VLA-perf是参照π0 及其衍生架构
#### 性能分析流程
分为核心计算逻辑和真实度验证两部分，有明确的公式和实测对标：
**核心计算逻辑：基于 roofline 模型的全链路延迟分模块拆解**
它把 VLA 端到端推理的总延迟，拆成模型计算延迟和数据传输延迟两部分，逐层精准计算：
- 第一步：算子级拆解。把每个模型组件（视觉 / VLM / 动作专家）拆成全连接、注意力、归一化等最基础的算子，算出每个算子的总计算量（FLOPs）和内存访问量（Bytes）；
- 第二步：roofline 模型算算子延迟。每个算子的执行延迟 = max (计算所需时间，内存访问所需时间)。
通俗类比：就像你开车送货，总时间取决于内存访问和算力，哪个慢，哪个就决定了最终耗时。这个模型能精准定位每个环节的瓶颈；
- 第三步：汇总模型总延迟。把所有算子的延迟加起来，得到单个组件的延迟，再汇总所有模型组件的延迟，得到模型总计算延迟；
- 第四步：计算数据传输延迟。跨设备的网络传输延迟 = 基础网络延迟 + 传输数据量 / 网络带宽，同设备内的本地数据传输延迟忽略不计；
- 第五步：汇总端到端总延迟。模型总计算延迟 + 数据传输总延迟 = 最终端到端延迟，再换算成推理频率（Hz）。
  
**保真度验证：和真实系统实测对标，证明评定结果靠谱**

论文用业界公认的、经过极致 CUDA 优化的 π0 模型（Triton 实现，RTX 4090 平台）做了严格对标，结果如下：
- VLA-Perf 预测的理论延迟，和真实系统实测的延迟，吻合度达到 73.3%~82.6%，且模型负载越高（比如输入更多相机画面），吻合度越高；
- 为什么不是 100%？因为 VLA-Perf 计算的是理论最优性能上限，假设软件优化做到极致、无额外开销；而真实系统里有内核启动、操作系统调度、运行时库的固定开销，所以会有差距；
- 论文明确说明：超过 80% 的保真度，完全足够用来做 VLA 模型和系统的设计指导、性能趋势分析、瓶颈定位，完全满足行业使用需求。

### 模型与推理系统设计策略
系统性与全维度全量性能变化规律--15条通用结论
#### 研究局限与未来反向：
- 场景覆盖有限：仅研究了机器人机械臂操作任务的 VLA 模型，没有覆盖自动驾驶、四足机器人、无人机、人形机器人全身控制等其他具身 AI 场景，这些场景有不同的约束（比如端侧强实时、高安全要求）和额外的模型组件（SLAM、运动规划、控制模块）；
- 链路覆盖不全：仅研究了 VLA 模型本身的推理延迟，没有考虑机器人的执行器延迟、传感器采集延迟、数据预处理 / 后处理延迟，而真实机器人的端到端延迟是全链路的，这些部分对实时性的影响极大；
- 没有考虑性能 - 精度的 trade-off：所有分析都基于「模型满足部署的精度要求」这个前提，只研究了推理性能，没有量化分析模型缩放、去噪步减少、上下文缩短等优化，对模型任务成功率、动作精度的影响，而真实部署中性能和精度必须平衡。
- 模型架构覆盖不全：目前主要基于 π0 的扩散式架构，对 Mamba 等状态空间模型、混合专家（MoE）架构的 VLA 模型没有覆盖，这些新架构的性能规律需要进一步分析；
- 硬件覆盖有限：仅测试了 NVIDIA 的 GPU，没有覆盖移动端 NPU、TPU、FPGA、ASIC 等其他机器人常用的推理加速器，这些硬件的计算和内存特性不同，性能规律也会有差异；
- 异步 / 双系统的稳定性分析不足：只提到了异步推理可能用旧观测数据影响动作质量，但没有量化分析异步窗口、双系统更新频率对机器人控制稳定性、任务成功率的影响，未来需要结合控制理论，做性能 - 稳定性的联合分析；
- 多机器人场景没有覆盖：只研究了单机器人 batch=1 的场景，没有研究多机器人共享推理服务器的多并发场景，而真实工业场景中，多机器人共享服务器是主流部署方式；
- 软件优化的影响没有深入：模型基于理论最优的软件实现，没有量化分析不同的推理框架（PyTorch/TensorRT/Triton）、算子优化、量化策略对实际性能的影响，而这些对真实部署的性能影响极大。
  
基于上述研究局限，未来的核心研究方向包括：拓展 VLA-Perf 的场景覆盖，适配人形机器人、自动驾驶等更多具身 AI 场景；构建感知 - 推理 - 执行全链路的性能建模体系；量化分析性能 - 精度 - 控制稳定性的 trade-off；适配更多新架构、新硬件的性能分析，完善 VLA 性能设计的全场景通用准则。
#### 15条通用结论：
1.对于像π0这样的小型VLA模型，现有的数据中心GPU已经可以实现与相机帧率相当的推理频率，而边缘GPU仍然受性能限制。
2.行动预测在所有硬件上都受内存限制，而视觉和VLM推理在除Jetson Thor之外的大多数GPU上受计算限制。
3.每个VLA组件的延迟随模型规模增加大致呈线性扩展。
4.虽然边缘和消费级GPU难以应对更大模型，但数据中心GPU仍然可以支持比基准模型大一个数量级以上的VLA模型实现实时推理。
5.数据中心GPU可以支持具有多达1K个过去时间步的实时长上下文VLA推理，而边缘和消费级GPU限制在大约100步。
6.噪步骤对行动专家延迟和端到端VLA延迟都有显著影响，而行动块大小的影响可以忽略不计。
7.在行动分块情况下，基于扩散的VLA推理比经典自回归VLA快一到两个数量级。
8.自回归VLA只有在生成少量行动标记或启用并行解码时才具有竞争力。
9.在大多数情况下，服务器端推理（即使仅使用消费级GPU）也显著优于在设备上推理，除非在网络条件极差的情况下。
10.设备-服务器协同推理通常比纯设备推理慢，并且总是比服务器端推理慢，使得该解决方案在实践中通常不具吸引力。
11.机器人执行和推理之间的异步性可以显著提高服务器端推理的系统吞吐量，尤其是在慢速无线网络连接下。
12.系统1和系统2之间的异步推理可以提高行动预测性能，性能增益高度依赖于硬件能力和网络延迟。
13.对于在设备上推理，最先进的边缘GPU（Jetson Thor）已经可以实现π0的10 Hz推理，但达到100 Hz需要模型层面的调整
14.对于边缘服务器推理，使用消费级GPU和无线网络可以实现10 Hz，而实现100 Hz需要数据中心GPU和更快的网络。
15.对于云服务器推理，在良好网络下10 Hz是可行的，而实现100 Hz通常需要异步推理

总结为：
- 明确了高端边缘 GPU（Jetson Thor）仅能满足 π0 模型 19Hz 的推理，仅能达到 10Hz 的基础实时性要求；A100/H100/B100 数据中心 GPU 可实现 61.7Hz 以上的推理，匹配相机帧率级实时性；同时验证了服务端推理在绝大多数网络场景下优于端侧推理，仅 4G 及以下极差网络环境适合端侧部署。
- 验证了扩散式 VLA 在动作分块场景下，比原生自回归 VLA 快 1~2 个数量级；去噪步数对延迟呈线性影响，而动作块大小对延迟影响极小，因此 VLA 设计应优先优化去噪步数，而非缩减动作块大小。
- 确数据中心 GPU 可支持 1K 步历史帧的长上下文 VLA 实时推理（11.7Hz），而边缘 / 消费级 GPU 仅能支持约 100 步的上下文，为长时序 VLA 模型设计提供了明确边界
- 量化了异步推理在弱网环境下可带来 2.63~5.99 倍的吞吐量提升，双系统推理在高端硬件 + 高速网络下可实现 2.24 倍的速度提升，同时明确了弱网环境下其收益会大幅衰减。
#### 内在联系
所有优化手段都围绕 Roofline 模型的核心逻辑展开，核心纽带是算子强度与硬件平衡 OI 的匹配度：模型架构、参数设计决定了负载的算子强度，硬件选型决定了平衡 OI 与性能天花板，部署方式、网络环境决定了实测性能能否接近理论上限，异步 / 双系统设计则是在固定天花板下，最大化系统吞吐量的补充手段，共同决定了 VLA 推理的最终实时性表现。
#### 相互制约关系
核心形成三大双向制约：
- 模型规模与硬件能力的制约：模型参数规模直接决定了硬件的最低算力、显存、带宽要求，硬件能力上限则直接决定了可部署的 VLA 模型规模与实时性边界；
- 算力与内存带宽的制约：二者共同决定硬件的性能天花板，单方面提升任一维度，都无法突破另一维度的约束，低 OI 的动作专家永远受内存带宽限制，高 OI 的 VLM / 视觉编码器永远受算力限制；
- 部署策略与网络性能的制约：服务端推理的算力优势，完全受网络性能的制约，网络延迟可完全抵消硬件的算力优势，仅在网络条件达标时，服务端推理才优于端侧部署。
#### 落地优先级
严格遵循先定约束边界，再补优化增益；先保数量级提升，再做百分比优化的原则，优先级从高到低为：
- 第一优先级：推理部署位置选型，直接决定性能基线，选错会导致数量级的性能差距；
- 第二优先级：VLA 模型架构选型，扩散式架构比原生自回归架构快 1~2 个数量级，是唯一能带来数量级延迟降低的设计决策；
- 第三优先级：瓶颈硬件的选型与配置，优先匹配短板项的硬件能力，非瓶颈项的硬件升级无实质收益；
- 第四优先级：扩散模型去噪步数调整，与延迟呈严格线性关系，调整成本极低、收益极高；
- 第五优先级：模型规模缩放、上下文长度配置，仅带来线性的延迟变化，且直接影响模型精度；
- 第六优先级：异步 / 双系统推理策略，仅为固定天花板下的增益补充，无法突破基础配置的性能上限；
- 最低优先级：软件层面的推理优化、动作块大小调整，仅带来百分比级的性能增益，是最后一步的精细化优化。
